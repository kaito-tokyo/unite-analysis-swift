# 味方の反応窓

味方の反応窓は、プレイヤーの行動が味方へ一時的な選択肢を作った場面を、結果だけでなく知覚、実行可能性、行動、出力の順に検証する任意の分析モデルである。通常の試合振り返りに必須とせず、「味方が追撃しなかった」などの解釈が場面の意味を左右するときだけ使う。

## 語彙と証拠

作られた機会を、進入路、露出した対象、吸収されたクールダウン、移動させられた敵、一時的な人数差、得点窓、オブジェクト圧力、安全な離脱のいずれかとして記述する。分類できない場合は観察した盤面変化だけを書く。

各味方について次の証拠を順に確認する。

1. **知覚**: 同じ画面またはミニマップに機会が現れたか、視界、カメラ外、クイックチャット、集合動作から知り得たか。不明なら「知覚不明」とする。
2. **実行可能性**: 距離、経路、移動速度、技とバトルアイテムのクールダウン、HP、妨害、敵の脅威、タイミング、撤退条件、得点やファームなどの競合タスクを確認する。必要なHUDや画面外情報がなければ「実行可能性不明」とする。
3. **行動**: 進入、対象変更、技使用、ゾーニング、カバー、得点、オブジェクト攻撃、退路確保、待機、撤退など、観察できる反応を記録する。
4. **出力**: ダメージ、KO、得点、オブジェクトだけでなく、敵の移動、時間購入、クールダウン消費、味方の安全、次の配置も追う。

最終状態は次のいずれかとする。

- **使わなかった**: 味方が機会を知覚でき、空間的・機械的にも実行可能だった証拠があり、それでも対応行動が確認できない。
- **使えなかった**: 距離、視界、クールダウン、HP、脅威、タイミング、撤退、競合タスクなど、利用を妨げた制約が確認できる。
- **視覚的に不明瞭な形で使った**: 味方の行動は機会に反応しているが、直後のダメージ、KO、得点、オブジェクト変換としては見えない。
- **判定不能**: 知覚または実行可能性を確立できない。単に明白な変換がないことを「使わなかった」と言い換えない。

実行可能性を確立できない限り、責任、消極性、判断ミスを味方へ帰属させない。

## 追跡workflow

1. contact sheetまたは広い`extract-clip`で、機会が作られる前の味方配置、敵配置、競合タスクを確認する。
2. プレイヤーの行動が何を変え、いつ反応窓が開閉したかを、必要なら`frame-burst`で確定する。
3. 同じ時刻帯のフル画面、ミニマップ、味方状態、HUDから、各味方の知覚可能性と実行可能性を別々に評価する。
4. 窓の後まで追い、味方の行動と、直接・間接の出力を記録する。短いクリップだけで出力が終わらない場合は場面境界を広げる。
5. 上の4状態のいずれかへ暫定分類し、欠けた証拠と別解釈を併記する。
6. プレイヤーへ、通話、クイックチャット、期待した合流、見えていた敵、味方の意図、撤退判断など、映像にない情報を尋ねる。回答が知覚、実行可能性、意図を変える場合は、最初の視覚分類と因果説明を更新する。

成功した変換と逃した変換のどちらにも同じ証拠ゲートを使う。ユーザーの説明は映像を無効にするものではなく、映像から分からない通信と意図を補う因果証拠として扱う。
